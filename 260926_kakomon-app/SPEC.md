# 応用情報 午前 過去問アプリ 仕様書

2026-09-26 grill-me セッションでの決定事項（経緯は [log_grillme_260926-1.md](log_grillme_260926-1.md)）。

## 1. 概要

| 項目 | 内容 |
|---|---|
| 対象 | 応用情報技術者試験 午前問題（1回80問・四択） |
| 利用者 | 本人のみ |
| 利用形態 | スマートフォン／PCのブラウザで毎日使うWebアプリ |
| 元データ | IPA 公開の問題PDF・解答PDF（https://www.ipa.go.jp/shiken/mondai-kaiotu/index.html） |
| 格納先 | `260926_kakomon-app/` |
| 公開 | GitHub Pages（`seatks/apps`、master ブランチのルートから配信）<br>`https://seatks.github.io/apps/260926_kakomon-app/` |

## 2. 収録範囲

1. まず最新の1回分（80問）だけを変換して試す。
2. 問題がなければ直近5年分（約10回・約800問）に広げる。2020年春期は試験中止のため存在しない。

## 3. 機能

### 3.1 出題モード（初版はこの2つのみ）

| モード | 出題 |
|---|---|
| ランダム10問 | 収録した全問から、セット内で重複しないように10問を完全ランダムに選ぶ（未解答を優先しない） |
| 復習 | 復習リストからランダムに最大10問を選ぶ（10問未満ならリストの全問） |

後回しにする機能：模試モード（80問通し）、分野別の出題、Service Worker によるオフライン対応。

### 3.2 復習リストのルール

- どちらのモードでも、**不正解なら復習リストに追加**する（すでに入っていれば何もしない）。
- **復習モードで正解したときだけ外す**。ランダム出題でたまたま正解しても外さない（理解不足を補うのが目的のため）。

### 3.3 画面

**ホーム**
- 「ランダム 10問」ボタン
- 「復習する（残り N問）」ボタン（0問のときは押せない表示）
- 解いた問題数（X / 全問数）、正答率（全解答中の正解の割合：Σcorrect ÷ Σtries）
- 収録回の一覧
- 履歴の書き出し／読み込み（下に小さく）
- 出典表記

**出題**
- 「問 n/10」と出典（例：R7秋 問42）を表示
- 問題文と図（図はタップで拡大）
- 選択肢ア〜エを縦に並べたボタンで表示。選択肢が図の中にある問題では、ボタンに記号だけを表示する
- 1回タップした時点で解答を確定し、選び直しはできない。すぐに正誤と正解を表示し、選んだボタンと正解のボタンに色を付ける
- 「次へ」で次の問題に進む
- 途中で中断した場合、解いた問題までの結果は保存し、セットは破棄する

**結果**
- 「N/10 正解」
- **全10問**について、問題文の冒頭・正誤（○／×）・正解を表示する
- 各問題の解説と参考URLは、折りたたんで表示し、タップで開く。解説がまだない問題は「解説準備中」と表示する
- 「もう1セット」「復習へ」「ホームへ」の各ボタン

## 4. データ

### 4.1 ファイル構成

```
260926_kakomon-app/
  index.html  style.css  app.js  storage.js
  manifest.webmanifest  icon-*.png     ← ホーム画面に追加するためのファイル
  check.html                           ← 変換結果を目視確認するページ
  data/
    index.json                         ← 収録している回の一覧（起動時に読む）
    2025A.json                         ← 1回分80問（A=秋期、S=春期）
  img/2025A/042-1.png                  ← 図・表の画像
  tools/
    pdf/          ← IPAのPDF（.gitignore の対象。gitには入れない）
    render.py     ← 問題PDFのページ → 座標グリッド付きPNG（書き起こし用）
    build.py      ← 書き起こし＋解答PDF → data/*.json・図のPNG・確認用ページ画像
    validate.py   ← 形式チェック
    overrides/<回ID>/*.json  ← Claudeの書き起こし（問題文・選択肢・ページ・図の切り出し範囲）
    work/         ← 作業用の画像（.gitignore の対象）
```

### 4.2 問題データ（1問分）

```json
{
  "id": "2025A-042",
  "exam": "令和7年度 秋期",
  "number": 42,
  "field": "technology",
  "question": "問題文（プレーンテキスト、改行あり）",
  "figures": ["img/2025A/042-1.png"],
  "choices": { "ア": "…", "イ": "…", "ウ": "…", "エ": "…" },
  "answer": "ウ",
  "explanation": "正解がウである理由（200〜400字）",
  "references": [{ "title": "ページ名", "url": "https://…" }],
  "needsReview": false,
  "pages": [3]
}
```

- `id` は回＋問番号で、回をまたいでも一意にする。履歴はこの `id` で問題を指す。
- `question` はプレーンテキストにする。表示するときにHTMLとして解釈しない。上付き・下付き文字などはUnicode文字で表し、表現しきれない数式や表は画像にする。
- 選択肢が図の中にある問題では `choices: null` にし、図のほうに選択肢を含める。
- `field` は解答PDFの分野欄（Ｔ／Ｍ／Ｓ）から `technology` / `management` / `strategy` を決める。
- 上線は結合文字（例：A̅）、上付き・下付き文字はUnicode文字で表す。原本の下線による強調は、結合下線（U+0332）で表す。
- 選択肢が表になっている問題は、選択肢を文章に直す（例：「ノード数 2,000／総理論ピーク演算性能 320 TFLOPS」）。
- `pages` は、原本でその問題が載っているページ（0始まり）。`check.html` だけが使う。
- 変換は `python tools/render.py <PDF名> <回ID>` → 書き起こし → `python tools/build.py <PDF名> <回ID>` → `python tools/validate.py <回ID>` の順に行う（例：`2025r07a 2025A`）。`build.py` は既存の解説を引き継ぐ。
- 800問を解説込みで収録しても合計1〜2MB程度なので、起動時に全ファイルを `fetch` で読み込む。

### 4.3 解答履歴（localStorage）

キー：`kakomon-app:v1`

```json
{
  "version": 1,
  "stats": {
    "2025A-042": { "tries": 3, "correct": 1, "last": "correct", "lastAt": "2026-09-26T08:12:00+09:00" }
  },
  "review": ["2025A-042", "2025A-007"]
}
```

- 端末ごとに保存し、同期はしない。
- **書き出し**：中身をそのまま `kakomon-backup-YYYYMMDD.json` としてダウンロードする。
- **読み込み**：件数を示した確認ダイアログを出したうえで、**全部を上書き**する。`version` やデータの形が正しくないファイルは読み込まず、エラーを表示する。

## 5. 解説の作り方

- 変換時に事前に生成し、JSONに入れておく。アプリの実行時には生成しない。
- **正解の根拠はIPAの解答PDFだけ**とする。解説サイトの内容と食い違う場合はIPAを優先し、`needsReview: true` にする。
- 解説は自分の言葉で200〜400字にまとめる。参考サイトの文章はコピーしない。
- 参考URLは1〜3件。IPAのシラバスや用語の一次情報を優先し、次に定番の過去問解説サイトを使う。
- 10問ずつ生成する。

## 6. 技術方針

- ライブラリなし・ビルドなしのHTML/CSS/JavaScript（ES modules）で作る。
- スマホを基準にしたデザインにし、`prefers-color-scheme` でダークモードに対応する。
- ホーム画面に追加できるようにする（manifest とアイコン）。Service Worker は初版では入れない。
- データは `fetch` で読み込むため、手元での確認には VS Code の Live Server などのローカルサーバーを使う（`index.html` をダブルクリックで開いても動かない）。
- PDFの変換には Python と PyMuPDF を使う。
- **問題PDFはページ全体が画像になっていて、テキストの層がない**（令和3〜7年度の全回で確認済み）。そのため、問題文と選択肢は Claude がページ画像を読んで書き起こす。図の切り出し範囲も Claude が決め、`tools/overrides/<回ID>/*.json` に記録する。
- `check.html` では、書き起こした文章と原本の画像を並べて表示し、見比べて確認する。読み取りに自信がない箇所がある問題は `needsReview: true` にする。
- 解答PDFはテキストの層があるので、スクリプトで読み取る。
- 出典として「IPA 応用情報技術者試験 ○年度○期 午前 問○」を表示する。公開する前に、IPAの「過去問題の使用方法」で利用条件を確認する。

## 7. 開発の手順

1. 最新1回分（令和7年度秋期 `2025r07a`）を変換する（解説なし）。`check.html` で目視確認する。
2. アプリを作る（3画面・履歴・復習・書き出しと読み込み）。
3. GitHub Pages で公開し、スマホで数日使う。
4. 80問分の解説を生成し、`needsReview` の付いた問題を見直す。
5. 直近5年分に広げる。
